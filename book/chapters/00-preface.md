# 写在前面：这本书怎么读

当你第一次打开一个大型工程，最容易遇到的困难通常不是“某一行代码看不懂”，而是“不知道应该先打开哪个文件”。本书要帮助你建立这张地图。我们以 OpenAI 的开源 Codex 工程为对象，从终端、目录和程序入口讲起，最后走到会话、工具、安全边界以及一次可撤销的小练习。

你可以把本书当成一位陪读者：它会告诉你为什么要看一个文件、先看哪几个名称、看完后应该能回答什么。它不会要求你在开始前掌握 Rust，也不会要求你先编译整个仓库。

## 我们说的“当前工程”是哪一份

本书介绍的源码位于上游仓库 [openai/codex](https://github.com/openai/codex)，基准提交为：

```text
57d4fac64adbcaed0523ca6bf8d58c4ef6875157
```

书稿整理日期为 2026 年 10 月 20 日。正文中指向源码的链接固定到这个提交，方便你在以后仍能找到同一段代码。书稿独立发布在 [Aias00/codex-engineering-book](https://github.com/Aias00/codex-engineering-book)，也可以[在线阅读](https://aias00.github.io/codex-engineering-book/)。书稿仓库保存章节、插图、构建脚本和阅读网站，不包含 Codex 的完整源码，也没有为了写书修改上游业务实现。

请分清两个目录：读源码、运行 Rust 练习时使用 `openai/codex` 的检出目录；修改本书、生成 EPUB 时使用 `codex-engineering-book` 的检出目录。只想看书，可以直接在线阅读或下载 EPUB，不必克隆任一仓库。

这是一份面向初学者的工程导读，并非 OpenAI 发布的官方产品手册。上游项目采用 Apache-2.0 许可证；短小的源码摘录用于解释工程行为。相关版权及许可见上游仓库的 `LICENSE` 和 `NOTICE`，本书仓库也在 `licenses/` 中保留对应副本。图示由书稿根据代码关系绘制，省略了分支、兼容层和错误路径，不应当作完整调用图。

本书以检出的源码、测试和仓库文档为依据。仓库中有些文档只包含前往官方站点的链接。编写时尝试访问相关官方页面受到访问限制，因此书中提供这些链接供继续查阅，不把它们的动态正文当作已经核验的证据。模型名称、账户套餐、费用和服务可用性均可能变化，请以实际账户与官方当前说明为准。

## 你会得到什么

读完以后，你应当可以用自己的话解释四件事：Codex 的本地程序与模型服务分别做什么；一个请求为什么会经过 app-server、core 和工具层；模型提出动作以后，哪些机制决定能否真正执行；在不改变业务代码的情况下，如何用一个小实验开始读 Rust。

“入门”的标准不是背出所有目录。能从一个用户问题找到相关模块，并用文件或测试支持你的解释，就是有效的进步。

## 三种阅读路线

| 你的目标 | 建议顺序 | 读完能做什么 |
|---|---|---|
| 先知道工程是什么 | 第 1、2、3、6、8 章 | 讲清请求到操作的大致过程 |
| 想开始读源码 | 第 1—7 章，再读第 12 章 | 从真实入口追踪一条路径，完成小实验 |
| 想用程序调用它 | 第 1、2、8、9、10、13 章 | 认识 SDK 的接口、权限和常见故障 |

每章先给一个具体问题，再解释必要概念。练习后有参考答案，建议你先停一下，尝试独立回答。个别章节里出现的同一概念会换个场景再解释，方便按需跳读。

## 书中命令怎样使用

正文标注“仓库根目录”的命令，始终指 **`openai/codex` 源码仓库的根目录**，也就是包含 `README.md`、`codex-rs/` 和 `sdk/` 的那一层。它不指本书仓库。克隆本书以后找不到 `codex-rs/` 是正常的；想跟着源码练习，需要另行克隆上游仓库，再进入那个目录：

```sh
git clone https://github.com/openai/codex.git
cd codex
git checkout 57d4fac64adbcaed0523ca6bf8d58c4ef6875157
```

这会把这份新克隆的源码切换到本书所用快照，方便对照文件和行号。若只想读代码，GitHub 上的固定提交链接也能满足需要。书稿的构建命令则明确从“本书仓库根目录”执行，具体见附录 B 与 `book/README.md`。

标注“示例”的输出表示你可以期待的形状，不保证每台机器逐字相同。书中用尖括号表示的占位符，例如 `<你的工程目录>`，需要先换成真实路径。

仅阅读文件、检查版本和查看 Git 差异，不会调用模型。安装依赖、构建和测试可能访问网络或占用较多磁盘。`codex` 对话与 SDK 的 `run` 示例会连接模型服务，需要已配置的认证，并可能消耗账户额度。本书没有实际发起这些模型请求，也没有把它们声称为运行成功的示例。

如果你使用 Windows，先把操作系统差异与程序概念分开：`rg`、Git 和编辑器在多平台可用，而 Shell 的引号、变量和管道写法可能不同。第 11 章会说明构建说明与平台实现之间的区别。

## 每次只带走一个问题

你不必一口气读完。读第 3 章时，只记住“主逻辑在哪里”；读第 6 章时，只追踪“一轮对话什么时候继续”；读第 8 章时，只判断“允许、审批和隔离分别解决什么”。当这些问题能接起来，目录就会从一串陌生名称变成一张可以使用的地图。
